# Внешние блоки и доставка сигналов

Исполнитель доставляет сигнал по одному проводу за раз, в порядке номеров
выходящих проводов. Новые отправки обрабатываются прежде оставшихся проводов
текущего блока: это обход в глубину. Для него используется явный стек заданий,
а не вложенные вызовы Python. Временные ссылки принадлежат заданиям доставки
и освобождаются после обработки или при ошибке.

Каждый провод передаёт сигнал в `on_signal(port, packet)` своего экземпляра
блока. Блок выбирает политику входов через `create_input_state`: её `receive`
получает имя входа и структуру и возвращает готовый набор сигналов либо ничего.
Стандартная политика `ConnectedInputs` ждёт по одному сигналу со всех
подключённых входов и отклоняет повторный сигнал на занятый вход. Состояние
входов также сообщает незаполненные входы через `waiting_for` и освобождает
сохранённые ссылки через `drain`. Если `receive` завершился ошибкой, он не
должен сохранять отклонённый сигнал.

Блоки, которым нужен независимый приём, реализуют собственный `on_signal`.
Оптимизатор сам обрабатывает и `start`, и `J`; график — каждый свой вход.
Остальные блоки используют выбранное состояние входов и вычисляют результат,
когда оно сообщает о готовности. Оба варианта снаружи имеют одинаковый метод
приёма сигнала. Общий исполнитель не выбирает поведение по типу блока.
Реализации блоков подключаются через каталог; автоматическая загрузка
произвольных файлов внешних блоков пока не реализована.

Обычный исполнитель предоставляет `execute_block(node, inputs, heap)`;
старый исполнитель с передачей голых чисел и прежние интерфейсы `execute`
и `execute_with_heap` удалены. Описания портов и параметры по умолчанию
внешних блоков определены самими блоками; библиотека и подготовка схемы
используют те же определения.

Блок может вернуть структуры на выходах, отдельный результат для просмотра и
дополнительные артефакты через `BlockOutcome`. `check_complete` проверяет
незавершённое состояние интерактивного блока, а `close` освобождает ресурсы.

Порядок проводов является частью схемы. Чтобы график показывал пробы по мере
их выполнения, сигналы на него должны отправляться до соответствующих веток,
продолжающих подбор. В частности, `J` сначала идёт на график, затем к
оптимизатору; сигнал сброса графика — раньше запуска оптимизатора.
