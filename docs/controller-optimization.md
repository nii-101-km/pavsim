# Оптимизатор и целевая функция на схеме

В инструкции используются русские названия интерфейса: выберите **RU**
в верхней панели. Начиная с PavSim 0.1.1 по умолчанию выбран **EN**;
переключение языка не меняет идентификаторы и формат моделей.

В категории Optimization доступны два звена. Подбор запускается общей
кнопкой **Run**; отдельной кнопки подбора в панели больше нет.

## Соединения

- Оптимизатор выдаёт три независимых числа p1/p2/p3.
- Подключите p1 к k1, p2 к k2 ПИ. Для ПИД p3 можно подключить к k3.
- Выход объекта подключите к входу y звена Целевая функция.
- Выход J целевой функции соедините со входом J оптимизатора.

Оптимизатор не знает о типе регулятора: параметры могут питать любую схему.
Сигнальный движок учитывает from_port и передаёт значение соответствующего
выхода. Старые блоки со скалярным выходом сохраняют поведение; скалярный
Разветвитель по-прежнему передаёт одинаковый сигнал на оба выхода.

## Настройки

Двойной клик по Оптимизатору:

- Алгоритм: покоординатный поиск, Нелдер–Мид, градиентный с численными производными.
- Подбирать при Run: выключение оставляет обычный расчёт с текущими параметрами.
- p1/p2/p3: текущие/начальные значения.
- Подбирать p1/p2/p3: выключенный параметр фиксируется на текущем значении.
- Нижняя и верхняя границы каждого подбираемого параметра.
- Максимум расчётов: от 20 до 300.

Выходы всегда остаются тремя; неподключённый p3 можно оставить свободным.
Для фиксированного параметра его границы не применяются.

Двойной клик по Целевой функции:

- Меню цели: IAE, ISE, время регулирования, перерегулирование, колебательность.
- Постоянная уставка выбранного сигнала.
- Допуск: 0.02 означает 2% амплитуды перехода.

Run выполняет пробные расчёты, затем итоговый расчёт. Значения найденных
параметров автоматически обновляются в звене. Для постоянного хранения
нажмите Save. При повторном Run подбор повторится, если не выключить
«Подбирать при Run». Если схема изменена во время подбора, ответ не применяется.

Пример: `demo_block_optimizer` (время 10, шаг 0.02, RK4).
ПИ управляет апериодическим звеном. При p1=p2 в границах [0,5] поиск IAE
находит значения около 5, сокращая IAE примерно с 5.98 до 0.20.
Выключенный p3 остаётся равным 7. Это пример проверки, не рекомендуемые
коэффициенты для другого объекта. Файл: examples/demo_block_optimizer.json.

## Цели и алгоритмы

Ошибка = уставка − вход y. IAE — интеграл модуля ошибки, ISE — интеграл
квадрата ошибки; интегрирование трапециями по отсчётам. Для IAE/ISE выход J
равен накопленному интегралу, а завершённый пробный расчёт оценивается
по его конечному значению.

Время регулирования — момент окончательного входа в полосу допуска.
Удержание должно занимать минимум последние 10% заданного времени:
единственный удачный последний отсчёт не считается регулированием.
Перерегулирование — превышение уставки в направлении перехода относительно
его амплитуды. Колебательность — избыточная вариация:
(сумма |приращений| − |полное перемещение|)/(2·амплитуда перехода).
Если амплитуда перехода нулевая, масштаб = max(|уставка|, 1).

Для последних трёх целей предпочтение отдаётся вариантам с удержанием
уставки; незавершённый переход штрафуется, чтобы неподвижный выход вдали
от уставки не выиграл с нулевым перерегулированием. Выход J — оценка для
минимизации (время нормируется горизонтом, перерегулирование — амплитудой).
В конце расчёта оценка уточняется по полному ряду отсчётов.
При равной оценке предпочтение отдается меньшим IAE, затем ISE.

Все алгоритмы работают с нормированными координатами в границах и общим
бюджетом, по умолчанию стартуют от текущих значений параметров. Нелдер–Мид выполняет
отражение, растяжение, сжатие и уменьшение симплекса. Градиентный метод
вычисляет производные конечными разностями и уменьшает шаг при неудачном
спуске. На ступенчатых критериях, например времени регулирования, полезное
направление спуска может отсутствовать. Глобальный минимум не гарантируется.

Не более 10000 шагов на расчёт и 600000 отсчётов по заданному бюджету.
Несколько оптимизаторов обрабатываются последовательно, это не совместный
поиск всех параметров сразу. Пробные расчёты только выдают текущие значения
оптимизатора, поэтому вложенных запусков подбора внутри Engine нет.

## Проверки

Поведенческие проверки подтверждают независимые выходы, передачу номера порта
через Подсистему, совместимость Разветвителя, подбор без регулятора, RK4/Euler,
пять целей и пять алгоритмов, границы, бюджет, фиксированные переменные и
неизменность исходной схемы. Численный оптимум и влияние инерции проверяются
на независимых квадратичных функциях; модели ПИ проверяются отдельно.
Программный harness и браузерная проверка отмечаются как разные виды проверки.

Старый endpoint /api/optimize сохранён для совместимости и использует те же
алгоритмы поиска. Текущие результаты полного набора — в [release notes 0.1.1](release-0.1.1.md).

## Расширенная строка параметров алгоритма

В звене есть поле «Параметры алгоритма (через ;)».
Формат: `имя=число; имя=число`. Пустая строка использует локальные настройки по умолчанию, без разведки.
Десятичный разделитель — точка; запятая в числе тоже принимается.

Общие параметры: initial_step, tolerance, shrink, max_iterations, random_starts.
Размеры заданы долями диапазонов, например initial_step=0.1 при границах
p1 [0,5] означает шаг 0.5 по p1. У Нелдера–Мида это начальный размер
симплекса по активным осям. Границы по-прежнему ограничивают пробные точки.

| Алгоритм | Настройки по умолчанию |
| --- | --- |
| Покоординатный | initial_step=0.25; tolerance=0.0005; shrink=0.5; max_iterations=1000 |
| Нелдер–Мид | initial_step=0.15; tolerance=0.0005; reflection=1; expansion=2; contraction=0.5; shrink=0.5; max_iterations=500 |
| Градиентный | initial_step=0.2; tolerance=0.00005; difference_step=0.001; shrink=0.5; backtracks=12; max_iterations=100 |
| Хук–Дживс | initial_step=0.1; tolerance=0.0005; pattern_step=1; shrink=0.5; max_iterations=500 |
| Тяжёлый шарик (Поляк) | initial_step=0.1; tolerance=0.00005; difference_step=0.001; momentum=0.5; shrink=0.5; backtracks=12; max_iterations=100 |

Примеры:

- Покоординатный: `initial_step=0.1; tolerance=0.0005; shrink=0.5`
- Нелдер–Мид: `initial_step=0.05; reflection=1; expansion=2`
- Градиентный: `initial_step=0.1; difference_step=0.0001; backtracks=15`
- Хук–Дживс: `initial_step=0.01; pattern_step=1; shrink=0.5`
- Тяжёлый шарик: `initial_step=0.05; momentum=0.5; difference_step=0.001`

Хук–Дживс не вычисляет производные: после проб по координатам выполняется
шаг вдоль успешного перемещения. pattern_step задаёт множитель этого
перемещения (больше 0, не больше 10). initial_step — размер проб по координатам.

Тяжёлый шарик использует численный градиент и инерцию Поляка:
v = momentum*v - initial_step*gradient. Здесь координаты нормированы
диапазонами параметров. initial_step — коэффициент перед градиентом,
а не предельное перемещение: размер шага также зависит от масштаба J.
momentum задаётся от 0 включительно до 1 исключительно. При неудачном
шаге инерция сбрасывается, затем шаг уменьшается с множителем shrink.
Границы соблюдаются проекцией. Возвращается лучший проверенный набор.
Для ступенчатых критериев вроде времени регулирования численный градиент
может оказаться нулевым; наличие метода не гарантирует улучшения любой цели.

Для тяжёлого шарика tolerance ограничивает минимальный коэффициент шага
и перемещение в нормированных координатах; для Хука–Дживса — размер проб.
Проверены известный квадратичный минимум, влияние инерции и pattern_step,
границы, недопустимые пробы, бюджет, фиксированные параметры, воспроизводимость
и выполнение новых методов через Эксперимент на ПИ-контуре.

Схема инерции: [Polyak momentum, Cornell](https://www.cs.cornell.edu/courses/cs4787/2025fa/lectures/lecture7.html).
Основа прямого поиска: [Hooke & Jeeves, 1961](https://doi.org/10.1145/321062.321069).

max_iterations ограничивает итерации алгоритма; «Максимум расчётов»
по-прежнему ограничивает число запусков модели. Это разные лимиты.
У градиентного метода tolerance — минимальный шаг при уменьшении шага,
у покоординатного — минимальный шаг поиска, у Нелдера–Мида — размер симплекса.
shrink и contraction должны быть строго между 0 и 1, expansion больше 1.
Неизвестные, повторные и некорректные настройки отклоняются с пояснением.
Строка сохраняется в JSON вместе с настройками звена.

Предварительная разведка по умолчанию выключена (`random_starts=0`).
Середина диапазона автоматически не проверяется. Для явного включения
добавьте `random_starts=5`: это пять воспроизводимых случайных проб
перед локальным поиском. Они не ограничены initial_step и входят в бюджет
расчётов. Разрешено целое число от 0 до 50. Если исходные значения вне
границ, локальный поиск стартует с их проекции на границы.
